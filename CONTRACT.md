# Pocket Stars v1 implementation contract

Offline Android app, native Java WebView shell + local HTML/CSS/JS. No network permissions/dependencies. Tablet 1200x1920 physical ~800x1280 CSS portrait; responsive landscape. Big touch buttons. Rosie and Jake, GBP integer pence, PIN-gated fines, parent-only admin/settlements, child removal of own unpaid chores, transaction history retained.

Parent owns web/core.js + web/pin.js + tests/ + android/; UI agent owns web/index.html, web/style.css, web/app.js and tests/ui.test.py; may update this contract when requested. Build agent owns tools/ and scripts/build-apk* ONLY. Do not overwrite one another.

## Core interface (global PocketStars)

`PocketStars.createState()` => initial JSON with version:1, kids:[{id:'rosie',name:'Rosie'},{id:'jake',name:'Jake'}], chores:[{id,label,pence,emoji,enabled,dailyLimit}], fines:[], entries:[], settlements:[] . Default chore tidy-room 50p, laid-table25p, fed-pet25p, homework50p. Defaults editable/disable-able. All defaults clearly examples, not real transactions.

`new PocketStars.Ledger(state, {now:()=>Date.now(),persist:(nextState)=>{...}})` . `ledger.data` getter clone. Storage persistence must succeed before commit or method throws and state unchanged.
`ledger.view(kidId)` => {kid, balancePence, weekEarnedPence, weekFinesPence (positive total), weekNetPence, chores, entries, settlements, weekStart} . `entries` newest-first all child history; each {id,kidId,typeId,kind:'chore'|'fine',label,pence signed,at ISO,weekStart,settlementId:null|string,voidedAt:null|string}. `chores` active types with `claimedToday` count and `available: true`. All chores repeatable: `dailyLimit` always 0; legacy dailyLimit1 normalized to0 when loaded without changing financial history. `settlements` newest first {id,kidId,at,netPence,paidPence,forgivenPence,entryIds}. Balance includes ALL unpaid nonvoided entries, not just this week. Weekly metrics calendar Monday in Europe/London, distinct from unpaid balance. Nothing autoclears on Monday.
`ledger.credit(kidId,choreId, requestId?)` => entry; child action; enforces enabled type. All existing and new chores repeatable, including twice on the same day. No fake demo entries.
`ledger.authorize()` sets ephemeral admin session for 2min AFTER PinVault success (UI responsible). `ledger.lock()` . `ledger.isAdmin` bool. Admin calls throw unless authorized; after each successful admin op renew session2min.
`ledger.fine(kidId,pence,requestId?)` => entry; parent sets integer pence amount (1..100000), recorded with label 'Fine'.
`ledger.settle(kidId)` => settlement; marks all unpaid entries settled, resets child's outstanding balance, never deletes history or affects other child. Negative net: paid0 and forgivenPence abs(net). UI must clearly label this as clearing debt instead of paying negative money. Confirm before calling. No unsettled entries => throws.
`ledger.voidEntry(entryId)` => voided entry; only unpaid nonvoided entries; leaves audit record; admin only.
`ledger.removeChore(kidId,entryId)` => voided entry, no admin required; only that child’s own unpaid nonvoided chore. Rejects fines, other-child entries, settled entries and repeat removal; persistence atomic, audit retained.
`ledger.upsertType(kind, {id? (new omit),label,pence,emoji,enabled,dailyLimit?})` => type; kind 'chore'; 1..100000 pence, trimmed label1..60, emoji optional, dailyLimit accepted for compatibility but all chores saved as0. Existing historical amounts/labels NEVER change. Archive uses enabled:false, no destructive type deletion.
`PocketStars.money(pence)` => GBP currency using Intl, negative -£0.50.
`PocketStars.parsePounds('0.50')` => 50; validates no negatives/no >2decimal; throws bad values.

## PIN interface (global PinVault)
`PinVault.hasPin()` => bool
`await PinVault.setup(pin,confirm)` => requires4..8digit PIN, no existing PIN, returns true; persisted salted PBKDF2-SHA256 hash, NOT plaintext. No default PIN. First-launch parent must set it. Do not expose code to children; no code in chat.
`await PinVault.unlock(pin)` => bool; rate-limit after5failures (30sec lockout persisted). On false use generic incorrect message, on thrown lockout display error.message. App calls ledger.authorize() only if true.
`await PinVault.change(oldPin,newPin,confirm)` => bool. Needs correct old pin, then fresh salt/hash.
`PinVault` uses Android.loadPin()/Android.savePin(JSON) when native bridge present; localStorage key pocket-stars-pin for browser tests. Hashing uses Android.derivePin(pin,saltHex) native method when present, else WebCrypto PBKDF2 120000 iterations,32bytes. Pin plaintext never saved.

## Data/persistence and native bridge
`Android.loadData()` returns JSON or '' . `Android.saveData(json)` returns bool (atomic local file save); throw/show error if false. Browser fallback localStorage 'pocket-stars-data'. On malformed data STOP and show recovery error; never silently reset ledger.
Native `Android.exportBackup(json)` creates document picker and writes JSON backup. Export only within parent area. Backup includes financial data and PIN HASH metadata via wrapper {format:'pocket-stars-backup',version:1,data:ledger.data,pin:...}; UI can obtain pin JSON via Android.loadPin or localStorage. Could omit PIN from export and require existing PIN for import, simplest only export ledger data. UI optional export download fallback browser.
Android: local assets under file:///android_asset/index.html, no INTERNET permission, disable WebView debugging and external URL navigation, native storage in app private files with atomic writes, no cleartext PIN, orientation unspecified supports rotation, configChanges handles preserve. Keep screen on while app open. Launcher icon label Pocket Stars. Runtime no server required.

UI parents controls: PIN first-run modal then Parents PIN gate, dismiss/lock button, forms for create/edit/archive chores; child selection in admin for single fine button (parent sets amount), settlement confirmation, transaction list undo unpaid entries, change PIN, export backup. Child home contains app title/Parents control and only Rosie/Jake big cards (with summary totals): no hero, banner, tagline or footer. Selected child star board is minimal: only repeatable chore buttons and a single large Fine button (no Unpaid balance, This week, or Your activity sections on the star board). Every fine addition on a child board prompts fresh parent PIN even if a ledger admin session exists; success opens the fine amount dialog on the SAME child board, not parent admin. Only authorize for the confirmed fine operation and always lock afterward (also on failure/cancel); retain authEpoch guards against asynchronous background unlock. No frequency chooser or daily-limit badges/disabled chore cards. Parent area retains existing authorized-session catalogue/undo/payment controls. Clear unpaid balance and 'This week' distinction on home cards and parent view. Touch targets >=56CSSpx, chore cards>=110px, highcontrast no tiny action links. All forms labels and buttons, no browser prompt/confirm (custom dialogs), textContent/escape all configurable labels (no XSS). Offline font stack system; no CDN. Warm cream/pink for Rosie, teal/navy for Jake, gold stars, no gratuitous gradients. Parent area must not be exposed merely by CSS toggling.
